Cách dùng tài liệu này

Mục tiêu

Bạn tự code 100% các bài tập, đối chiếu với đáp án và giải thích, để nắm chắc PHP trước khi vào Laravel. Tài liệu này bổ sung cho lộ trình Laravel (file laravel-crash-course-plan.pdf), không thay thế nó: lộ trình dạy lý thuyết Laravel, tài liệu này cho bạn chỗ luyện tay PHP thuần.

Quy trình làm một bài (làm đúng thứ tự)

  1. Đọc đề, dự đoán hoặc tự phác thảo cách làm trên giấy.
  2. Gõ code vào một file .php trong php-warmup, chạy bằng lệnh php ten-file.php.
  3. So sánh với mục "Kết quả khi chạy" trong đề (nếu có). Khác thì tự debug, nhìn lỗi PHP báo ở dòng nào.
  4. Kẹt hơn 15 phút mới mở đáp án. Đọc đáp án rồi đóng lại và viết lại từ trí nhớ.
  5. Làm thí nghiệm "phá code": đổi một dấu, một điều kiện, xoá một use, xem lỗi gì. Hiểu lỗi nhớ lâu hơn hiểu đúng.

Chạy file và đọc lỗi

  • Chạy: php ten-file.php. Kiểm tra phiên bản: php -v (tài liệu chạy kiểm tra trên PHP 8.5, yêu cầu tối thiểu 8.3).
  • Warning và Notice: chương trình vẫn chạy nhưng có vấn đề (thường là đọc key không tồn tại). Đừng bỏ qua.
  • Fatal error: Uncaught ...: ném exception mà không ai bắt. Đọc dòng đầu: loại lỗi và message; dòng #0 cho biết hàm nào, file nào, dòng nào.
  • Dùng print_r($x) hoặc var_dump($x) để xem nội dung biến, json_encode($x) để in gọn một dòng.

Mỗi bài có ★ (dễ), ★★ (vừa), ★★★ (khó, cần suy nghĩ). Bài dự đoán output được đánh dấu rõ: chỉ có code, không có kết quả mong đợi, bạn phải tự đoán trước khi chạy.

Quy ước về đáp án

Có nhiều cách đúng cho cùng một bài. Đáp án trong tài liệu là một cách rõ ràng và an toàn, không phải cách duy nhất. Nếu code của bạn cho cùng kết quả (kể cả các trường hợp biên), nó vẫn đúng. Hãy so sánh hai cách, hiểu vì sao đáp án chọn như vậy.

Phần chưa có trong tài liệu này

Các chủ đề PHP sau nằm trong lộ trình Laravel nhưng chưa có bài tập ở đây: interface, abstract class, trait, enum, static, namespace + Composer autoload (PSR-4), attribute, và dependency injection. Khi bạn học đến đó sẽ có thể bổ sung chương mới.

Checklist tự đánh giá cuối khoá

Đánh dấu khi bạn tự làm được không cần xem:

  • Giải thích được khác nhau của == / ===, ?? / ?:, isset / array_key_exists.
  • Biết array_filter giữ key và biết khi nào dùng array_values.
  • Phân biệt sort / asort / usort và biết hàm nào giữ key.
  • Viết được usort nhiều tiêu chí với <=>.
  • Viết được class có constructor promotion, private, readonly, ném và bắt exception.
  • Đọc/ghi được file, CSV, JSON; xử lý được file không tồn tại.
  • Phân biệt use ($x), use (&$x) và fn; viết được hàm trả về closure.
  • Giải thích được vì sao tìm nhị phân nhanh hơn và vì sao dùng hash map (isset) nhanh hơn in_array.

Closure và arrow function

Closure là hàm không tên, lưu vào biến và truyền đi như một giá trị. Laravel dùng closure khắp nơi: route (Route::get('/', function () {...})), DB::transaction(function () {...}), Collection (->map(fn ...)), đăng ký service vào container (bind('x', fn () => new X())).

Bài 10.1Closure bắt biến thế nào? Thí nghiệm A, B, C★★★

Chạy trong đầu ba đoạn code, đều bắt đầu bằng $x = 10, tạo closure, sau đó đổi $x = 99, rồi gọi closure. Dự đoán ba số in ra.

  • A: function () use ($x) { return $x; }
  • B: function () use (&$x) { return $x; }
  • C: fn () => $x
Code đề bài
<?php

declare(strict_types=1);

$x = 10;
$a = function () use ($x) {
    return $x;
};
$x = 99;
echo 'A: ', $a(), "\n";

$x = 10;
$b = function () use (&$x) {
    return $x;
};
$x = 99;
echo 'B: ', $b(), "\n";

$x = 10;
$c = fn () => $x;
$x = 99;
echo 'C: ', $c(), "\n";

Việc cần làm: ghi ra giấy kết quả bạn dự đoán, sau đó tự chạy để kiểm tra rồi mới xem đáp án.

Giải thích

  • a <=> b trả -1 nếu a < b, 0 nếu bằng, 1 nếu a > b.
  • Với chuỗi, so sánh theo thứ tự ký tự: 'a' đứng trước 'b' nên 'a' <=> 'b' là -1.

Đáp án 5.4Tự viết bubble sort cho mảng bài viết
Code đáp án
<?php

declare(strict_types=1);

$posts = [
    ['title' => 'A', 'views' => 5],
    ['title' => 'B', 'views' => 20],
    ['title' => 'C', 'views' => 11],
    ['title' => 'D', 'views' => 3],
    ['title' => 'E', 'views' => 40],
];

function handleSort(array $arr): array
{
    $n = count($arr);

    for ($i = 0; $i < $n - 1; $i++) {
        for ($j = 0; $j < $n - 1 - $i; $j++) {
            if ($arr[$j]['views'] < $arr[$j + 1]['views']) {
                $temp = $arr[$j];
                $arr[$j] = $arr[$j + 1];
                $arr[$j + 1] = $temp;
            }
        }
    }

    return $arr;
}

echo implode(', ', array_column(handleSort($posts), 'title')), "\n";
echo implode(', ', array_column($posts, 'title')), "\n";
Kết quả khi chạy
E, B, C, A, D
A, B, C, D, E

Giải thích thuật toán

  • Vòng ngoài $i đếm số lượt. Sau lượt đầu, phần tử nhỏ nhất (với sắp giảm dần) "chìm" về cuối; sau lượt hai, phần tử nhỏ thứ hai chìm về vị trí kế cuối; v.v.
  • Vòng trong $j so sánh cặp ($j, $j+1). Giới hạn $n - 1 - $i vì $i phần tử cuối đã vào đúng chỗ, không cần so sánh lại.
  • Đổi chỗ bằng biến tạm $temp: gán $arr[$j] vào $temp, rồi $arr[$j] = $arr[$j + 1], rồi $arr[$j + 1] = $temp.
  • Điều kiện < cho giảm dần (phần tử trước nhỏ hơn phần tử sau thì đổi). Đổi thành > được tăng dần.

Về tham số mảng

$arr trong hàm là bản sao (PHP truyền mảng theo giá trị, có cơ chế copy-on-write), nên $posts gốc không đổi. Dòng in cuối chứng minh.

Độ phức tạp

Hai vòng lồng nhau nên thời gian cỡ n² phép so sánh. Dùng để học hiểu; thực tế dùng usort (nhanh hơn nhiều, độ phức tạp n log n).

<?php

declare(strict_types=1);

    public function __construct(public string $name, private int $price) {}

    {

}

} catch (Error $e) {

}

Giải thích

  • public: truy cập được từ mọi nơi. private: chỉ truy cập được bên trong class đó. (Còn protected: class đó và class con.)
  • price là private nên bên ngoài đọc $p->price sẽ bị chặn bằng Error ("Cannot access private property"). Bên trong class, $this->price dùng thoải mái.
  • Muốn cho bên ngoài đọc giá thì viết một method getPrice(), hoặc cho phép đọc có kiểm soát. Ý nghĩa: bên ngoài không thể đặt giá thành số âm nếu ta không cung cấp cách đó. Đó là đóng gói (encapsulation).

  • Error là lớp cha của các lỗi nghiêm trọng của engine (TypeError, ...). Exception là cho lỗi nghiệp vụ. Cả hai đều implement Throwable.

Đáp án 7.5BankAccount: ném và bắt exception
Code đáp án
<?php

declare(strict_types=1);

class BankAccount
{
    private int $balance = 0;

    public function deposit(int $amount): void
    {
        if ($amount <= 0) {
            throw new InvalidArgumentException('Số tiền phải lớn hơn 0');
        }

        $this->balance += $amount;
    }

    public function withdraw(int $amount): void
    {
        if ($amount <= 0) {
            throw new InvalidArgumentException('Số tiền phải lớn hơn 0');
        }

        if ($amount > $this->balance) {
            throw new RuntimeException('Số dư không đủ');
        }

        $this->balance -= $amount;
    }

    public function balance(): int
    {
        return $this->balance;
    }
}

$acc->withdraw(300);

try {
    $acc->withdraw(5000);
} catch (InvalidArgumentException $e) {
    echo 'Đầu vào sai: ', $e->getMessage(), "\n";
} catch (RuntimeException $e) {
    echo 'Lỗi nghiệp vụ: ', $e->getMessage(), "\n";
} finally {
    echo 'Xong', "\n";
}

    $acc->deposit(-5);
} catch (InvalidArgumentException $e) {
    echo 'Đầu vào sai: ', $e->getMessage(), "\n";
} catch (RuntimeException $e) {

}

Giải thích

  • Hàm kiểm tra điều kiện sai trước rồi throw (cách viết "guard clause"), phần xử lý bình thường nằm cuối. Code phẳng, ít else lồng nhau.
  • private int $balance = 0 có giá trị khởi tạo ngay tại khai báo, nên không cần constructor.
  • InvalidArgumentException dùng khi đầu vào sai (lập trình viên gọi sai). RuntimeException dùng khi lỗi xảy ra lúc chạy do trạng thái (hết tiền, file mất). Cả hai kế thừa Exception.

Đáp án 7.6Cart: kết hợp class và array
Code đáp án
<?php

declare(strict_types=1);

final class Item
{
    public function __construct(
        public readonly string $name,
        public readonly int $price,
        public readonly int $qty,
    ) {}
}

class Cart
{
    private array $items = [];

    public function add(Item $item): void
    {
        $this->items[] = $item;
    }

    public function total(): int
    {
        return array_reduce(
            $this->items,
            fn (int $carry, Item $i): int => $carry + $i->price * $i->qty,
            0
        );
    }

    public function names(): array
    {
        $names = array_map(fn (Item $i): string => $i->name, $this->items);
        sort($names);

        return $names;
    }
}

$cart = new Cart();
$cart->add(new Item('Áo', 200000, 2));
$cart->add(new Item('Quần', 350000, 1));
$cart->add(new Item('Mũ', 50000, 3));

echo $cart->total(), "\n";
echo json_encode($cart->names(), JSON_UNESCAPED_UNICODE), "\n";
Kết quả khi chạy
900000
["Mũ","Quần","Áo"]

Giải thích

  • Item là Value Object bất biến, Cart quản lý trạng thái (mảng $items).
  • $this->items[] = $item thêm object vào cuối mảng thuộc tính.
  • total(): array_reduce với callback nhận Item $i (khai báo class type trong tham số callback). Tính 200000*2 + 350000*1 + 50000*3 = 400000 + 350000 + 150000 = 900000.
  • names(): array_map lấy tên, rồi sort (sắp tại chỗ) để theo thứ tự chữ cái. Lưu ý PHP sắp chuỗi theo mã byte nên tiếng Việt có dấu có thể không đúng thứ tự tự nhiên: 'Áo' có ký tự đầu là Á (mã lớn hơn M, Q), nên đứng cuối. Muốn sắp đúng tiếng Việt cần dùng Collator của extension intl.
  • Kiểu array ở thuộc tính chỉ nói "là mảng", không nói phần tử gì; PHP chưa có kiểu Item[] thật (chỉ ghi chú docblock).

Mở rộng

Thử thêm method isEmpty(): bool và remove(string $name): void (dùng array_filter rồi array_values). Đây chính là cách một Service Laravel quản lý giỏ hàng.

function loadExpenses(string $path): array
{

        throw new RuntimeException('Không tìm thấy file: ' . basename($path));

    $header = fgetcsv($handle);

}

{

        $byCategory[$row['category']] ??= 0;
        $byCategory[$row['category']] += $row['amount'];
    }

    arsort($byCategory);

    return [
        'total' => $total,
        'byCategory' => $byCategory,
        'top' => array_key_first($byCategory),
    ];
}

Đáp án 9.1Bubble sort có tham số hướng
Code đáp án
<?php

declare(strict_types=1);

function bubbleSort(array $arr, bool $desc = false): array
{
    $n = count($arr);

    do {
        $swapped = false;

        for ($i = 0; $i < $n - 1; $i++) {
            $outOfOrder = $desc ? $arr[$i] < $arr[$i + 1] : $arr[$i] > $arr[$i + 1];

            if ($outOfOrder) {
                [$arr[$i], $arr[$i + 1]] = [$arr[$i + 1], $arr[$i]];
                $swapped = true;
            }
        }
    } while ($swapped);

    return $arr;
}

echo implode(', ', bubbleSort([5, 2, 9, 1, 7])), "\n";
echo implode(', ', bubbleSort([5, 2, 9, 1, 7], true)), "\n";
echo implode(', ', bubbleSort([])), "|\n";
echo implode(', ', bubbleSort([3])), "\n";
Kết quả khi chạy

|
3

Giải thích

  • Vòng do ... while ($swapped) lặp lại các lượt duyệt cho tới khi một lượt không đổi chỗ nào, nghĩa là mảng đã đúng thứ tự. Đây là phiên bản có "dừng sớm", nhanh hơn bản hai vòng for cố định khi mảng gần như đã sắp.
  • $outOfOrder quyết định hai phần tử cạnh nhau có sai thứ tự không. Với tăng dần, sai khi phần tử trước lớn hơn phần tử sau; với giảm dần, sai khi phần tử trước nhỏ hơn. Đổi cả hai hướng chỉ bằng đổi dấu so sánh, trong một biểu thức điều kiện.
  • [$arr[$i], $arr[$i + 1]] = [$arr[$i + 1], $arr[$i]]; đổi chỗ hai phần tử mà không cần biến tạm (list destructuring). Vế phải tạo mảng tạm trước, rồi vế trái gán lại.
  • Mảng rỗng: $n - 1 = -1, vòng for không chạy, trả mảng rỗng. Mảng 1 phần tử: tương tự. Luôn thử các trường hợp biên này.

Lượt 1: so 3,1 đổi thành [1,3,2]; so 3,2 đổi thành [1,2,3]; có đổi nên lặp lượt 2. Lượt 2: không đổi, dừng. Kết quả [1,2,3].

function selectionSort(array $arr): array
{
    $n = count($arr);

    for ($i = 0; $i < $n - 1; $i++) {
        $minIndex = $i;

        for ($j = $i + 1; $j < $n; $j++) {
            if ($arr[$j] < $arr[$minIndex]) {
                $minIndex = $j;
            }
        }

        if ($minIndex !== $i) {
            [$arr[$i], $arr[$minIndex]] = [$arr[$minIndex], $arr[$i]];
        }
    }

    return $arr;
}

Đáp án 9.3Max, min và lớn thứ hai trong một lượt duyệt
Code đáp án
<?php

declare(strict_types=1);

function stats(array $arr): array
{
    if ($arr === []) {
        return ['max' => null, 'min' => null, 'second' => null];
    }

    $max = $min = $arr[0];
    $second = null;

    foreach ($arr as $x) {
        if ($x > $max) {
            $second = $max;
            $max = $x;
        } elseif ($x !== $max && ($second === null || $x > $second)) {
            $second = $x;
        }

        if ($x < $min) {
            $min = $x;
        }
    }

    return ['max' => $max, 'min' => $min, 'second' => $second];
}

echo json_encode(stats([5, 9, 2, 9, 7])), "\n";
echo json_encode(stats([5, 5, 5])), "\n";
echo json_encode(stats([])), "\n";

Giải thích

  • Ba biến theo dõi: $max, $min, $second. Khởi đầu max và min bằng phần tử đầu, second là null (chưa có).
  • Gặp số lớn hơn max: số max cũ trở thành second, rồi max nhận số mới. (Thứ tự gán quan trọng: phải lưu max cũ vào second trước khi ghi đè max.)
  • Gặp số không lớn hơn max: nó có thể là ứng viên second, nếu khác max (loại trùng) và lớn hơn second hiện tại (hoặc second còn null).

  • Với [5, 9, 2, 9, 7]: số 9 thứ hai không làm second = 9 vì $x !== $max là sai. Kết quả second = 7.
  • Với [5, 5, 5]: mọi số đều bằng max nên second mãi null.

Đáp án 9.4Tìm kiếm nhị phân và so sánh với tìm tuần tự
Code đáp án
<?php

declare(strict_types=1);

function binarySearch(array $sorted, int $target, int &$steps = 0): int
{
    $low = 0;
    $high = count($sorted) - 1;
    $steps = 0;

    while ($low <= $high) {
        $steps++;
        $mid = intdiv($low + $high, 2);

        if ($sorted[$mid] === $target) {
            return $mid;
        }

        if ($sorted[$mid] < $target) {
            $low = $mid + 1;
        } else {
            $high = $mid - 1;
        }
    }

    return -1;
}

function linearSearch(array $arr, int $target, int &$steps = 0): int
{
    $steps = 0;

    foreach ($arr as $i => $x) {
        $steps++;

        if ($x === $target) {
            return $i;
        }
    }

    return -1;
}

$nums = range(1, 1000);

$binSteps = 0;
$linSteps = 0;
echo 'binary: vị trí ', binarySearch($nums, 777, $binSteps), ', ', $binSteps, " bước\n";
echo 'linear: vị trí ', linearSearch($nums, 777, $linSteps), ', ', $linSteps, " bước\n";
echo 'không có: ', binarySearch($nums, 5000), "\n";
Kết quả khi chạy

linear: vị trí 776, 777 bước
không có: -1

Giải thích

  • Ý tưởng: mảng đã sắp thì so sánh với phần tử giữa. Nếu nhỏ hơn mục tiêu, mục tiêu nằm bên phải, bỏ cả nửa trái; ngược lại bỏ nửa phải. Mỗi bước loại một nửa.
  • $low và $high là hai đầu vùng còn nghi ngờ. Vòng lặp chạy khi $low <= $high. Hết vùng mà chưa thấy thì trả -1.
  • intdiv($low + $high, 2) chia lấy phần nguyên. Dùng / sẽ ra số thực.
  • Quan trọng: khi bỏ nửa, phải + 1 hoặc - 1 ($low = $mid + 1, $high = $mid - 1). Nếu viết $low = $mid có thể lặp vô hạn.
  • int &$steps: dấu & truyền tham chiếu, nên hàm sửa trực tiếp biến $binSteps bên ngoài. Cách PHP "trả thêm một giá trị" ngoài return.

Mảng 1000 phần tử: nhị phân tối đa khoảng 10 bước (log2(1000)), tuần tự 777 bước. Khi mảng lớn gấp đôi, nhị phân chỉ thêm 1 bước. Đó là sức mạnh của chia để trị, và là lý do index cơ sở dữ liệu nhanh.

Đáp án 9.5Tìm cặp có tổng bằng K (hai cách)
Code đáp án
<?php

declare(strict_types=1);

function pairsNested(array $arr, int $k): array
{
    $pairs = [];
    $n = count($arr);

    for ($i = 0; $i < $n; $i++) {
        for ($j = $i + 1; $j < $n; $j++) {
            if ($arr[$i] + $arr[$j] === $k) {
                $pairs[] = [$arr[$i], $arr[$j]];
            }
        }
    }

    return $pairs;
}

function pairsWithSum(array $arr, int $k): array
{
    $seen = [];
    $pairs = [];

    foreach ($arr as $x) {
        $need = $k - $x;

        if (isset($seen[$need])) {
            $pairs[] = [$need, $x];
        }

        $seen[$x] = true;
    }

    return $pairs;
}

$nums = [1, 5, 3, 7, 4, 6, 2];
echo 'nested: ', json_encode(pairsNested($nums, 8)), "\n";
echo 'hash:   ', json_encode(pairsWithSum($nums, 8)), "\n";
Kết quả khi chạy

Cách 1: hai vòng lồng nhau

Vòng ngoài chọn $arr[$i], vòng trong chọn $arr[$j] với $j bắt đầu từ $i + 1 (tránh ghép số với chính nó và tránh đếm trùng cặp (a,b) và (b,a)). Số phép so sánh cỡ n²/2.

Cách 2: dùng sổ (hash map)

  • $seen là mảng kết hợp với key là các số đã gặp. Kiểm tra isset($seen[$need]) gần như tức thì (PHP dùng bảng băm), không phải quét lại cả mảng.
  • Mỗi số x chỉ cần một lần kiểm tra K - x đã có trong sổ chưa, rồi ghi x vào sổ. Tổng chỉ n bước.
  • Cặp được phát hiện khi gặp số thứ hai nên thứ tự cặp trong kết quả khác cách 1, nhưng tập cặp giống nhau: {1,7}, {5,3}, {6,2}.
  • Số 4: K - 4 = 4 nhưng trong mảng chỉ có một số 4, nên không tạo cặp (4,4). Cách 2 xử lý đúng vì ta chỉ ghi 4 vào sổ sau khi kiểm tra.

Dùng mảng kết hợp để đổi thời gian lấy bộ nhớ: từ n² xuống n. Đây là kỹ thuật dùng nhiều nhất trong các bài thuật toán. Ngược lại, in_array() trên mảng thường phải quét tuần tự nên chậm hơn isset trên key.

declare(strict_types=1);

function duplicates(array $arr): array
{
    $count = [];

        $count[$x] ??= 0;
        $count[$x]++;
    }

}

Đáp án 9.8Kiểm tra ngoặc hợp lệ bằng ngăn xếp
Code đáp án
<?php

declare(strict_types=1);

function isValidBrackets(string $s): bool
{
    $pairs = [')' => '(', ']' => '[', '}' => '{'];
    $stack = [];

    foreach (str_split($s) as $ch) {
        if (in_array($ch, $pairs, true)) {
            $stack[] = $ch;
            continue;
        }

        if (array_pop($stack) !== $pairs[$ch]) {
            return false;
        }
    }

    return $stack === [];
}

foreach (['([]{})', '([)]', '((', '', ')('] as $s) {
    echo json_encode($s), ' => ', var_export(isValidBrackets($s), true), "\n";
}
Kết quả khi chạy
"([]{})" => true
"([)]" => false
"((" => false
"" => true
")(" => false

Giải thích

  • $pairs ánh xạ ngoặc đóng sang ngoặc mở tương ứng. Dùng làm hai việc: in_array($ch, $pairs, true) kiểm tra $ch có phải ngoặc mở không (giá trị của $pairs), và $pairs[$ch] cho ngoặc mở cần khớp.
  • Ngoặc mở: $stack[] = $ch đẩy vào (push). continue sang ký tự tiếp.
  • Ngoặc đóng: array_pop($stack) lấy phần tử cuối ra (pop). Nếu ngăn xếp rỗng, array_pop trả null, khác $pairs[$ch], nên trả false ngay (trường hợp ')(', đóng khi chưa mở). Nếu lấy ra không khớp loại ngoặc ('([)]'), cũng false.
  • Cuối cùng, ngăn xếp phải rỗng ($stack === []). Chuỗi '((' còn dư 2 ngoặc mở nên false.
  • Chuỗi rỗng hợp lệ (true) vì không có gì sai.

Vì sao dùng stack

Ngoặc mở gần nhất phải được đóng trước (vào sau, ra trước: LIFO). Đó chính là tính chất của ngăn xếp. Cơ chế tương tự dùng khi trình biên dịch phân tích cú pháp và khi duyệt cây thư mục.

        'subtotal' => $subtotal,
        'discount' => $discount,
        'shipping' => $shipping,
        'total' => $subtotal - $discount + $shipping,
    ];
}

$lines = [
    new Line(new Product('Áo', 200000), 2),
    new Line(new Product('Mũ', 50000), 1),
];

foreach (['none', 'vip10', 'minus50k'] as $code) {
    echo $code, ': ', json_encode(checkout($lines, $code, $discounts)), "\n";
}

try {
    checkout($lines, 'abc', $discounts);
} catch (InvalidArgumentException $e) {
    echo $e->getMessage(), "\n";
}

    new Line(new Product('Áo', 200000), 0);
} catch (InvalidArgumentException $e) {

Thiết kế

  • Product và Line là Value Object bất biến (final, readonly). Kiểm tra dữ liệu hợp lệ ngay trong constructor của Line: không thể tồn tại một Line có qty <= 0. Nguyên tắc: đối tượng hợp lệ ngay từ lúc sinh ra.
  • $discounts là mảng ánh xạ mã sang closure. Thêm mã mới chỉ cần thêm một dòng, không sửa hàm checkout (thiết kế mở rộng được). Mỗi closure nhận tổng tiền và trả số tiền giảm.
  • checkout kiểm tra mã bằng isset($discounts[$code]), rồi gọi $discounts[$code]($subtotal): lấy closure từ mảng bằng key rồi gọi ngay.

Tính toán (đơn mẫu)

  • Subtotal: 200000*2 + 50000*1 = 450000.
  • none: giảm 0, tiền sau giảm 450000 thuộc khoảng 200000 đến dưới 500000 nên ship 15000, total = 450000 + 15000 = 465000.
  • vip10: giảm 45000, còn 405000 (vẫn trong khoảng 200000 đến dưới 500000) nên ship 15000, total = 450000 − 45000 + 15000 = 420000.
  • minus50k: giảm 50000, còn 400000, ship 15000, total = 450000 − 50000 + 15000 = 415000.
  • Phí ship tính trên số tiền sau giảm (quyết định thiết kế; đề có thể chọn tính trước giảm, hãy thử đổi và xem total thay đổi).

Điểm hay để thảo luận

  • min($t, 50000) đảm bảo không giảm quá tổng tiền hàng.
  • intdiv trả số nguyên (làm tròn xuống), tránh số thực với tiền.
  • Hai khối try/catch đều bắt InvalidArgumentException nhưng đến từ hai nơi khác nhau: chứng tỏ exception đi xuyên qua nhiều lớp gọi hàm.

Code đáp án
<?php

declare(strict_types=1);

final class Product
{
    public function __construct(
        public readonly string $name,
        public readonly int $price,
    ) {}
}

final class Line
{
    public function __construct(
        public readonly Product $product,
        public readonly int $qty,
    ) {
        if ($qty <= 0) {
            throw new InvalidArgumentException('Số lượng phải lớn hơn 0');
        }
    }

    public function subtotal(): int
    {
        return $this->product->price * $this->qty;
    }
}

function loadOrder(string $path): array
{
    if (!file_exists($path)) {
        throw new RuntimeException('Không tìm thấy file: ' . basename($path));
    }

    return json_decode(file_get_contents($path), true, 512, JSON_THROW_ON_ERROR);
}

$lines = [
    new Line(new Product('Áo', 200000), 2),
    new Line(new Product('Mũ', 50000), 1),
    new Line(new Product('Quần', 350000), 1),
];

$rows = array_map(
    fn (Line $l): array => [
        'name' => $l->product->name,
        'qty' => $l->qty,
        'subtotal' => $l->subtotal(),
    ],
    $lines
);

usort($rows, fn (array $a, array $b): int => $b['subtotal'] <=> $a['subtotal']);

$report = ['topProduct' => $rows[0]['name'], 'lines' => $rows];

$path = __DIR__ . '/order.json';
file_put_contents($path, json_encode($report, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));

$back = loadOrder($path);
echo $back['topProduct'], "\n";
echo count($back['lines']), "\n";

unlink($path);

try {
    loadOrder(__DIR__ . '/khong-co.json');
} catch (RuntimeException $e) {
    echo $e->getMessage(), "\n";
}

Giải thích

  • array_map biến mỗi Line (object) thành một mảng kết hợp gọn để lưu JSON. Object readonly có thuộc tính public nên đọc được bằng ->, nhưng với những object phức tạp nên viết method toArray() riêng.
  • usort với $b['subtotal'] <=> $a['subtotal'] sắp giảm dần: Áo 400000, Quần 350000, Mũ 50000. topProduct là Áo.
  • json_decode($json, true, 512, JSON_THROW_ON_ERROR): tham số 3 là độ sâu tối đa, tham số 4 là cờ. JSON_THROW_ON_ERROR ném JsonException khi JSON hỏng thay vì trả null âm thầm.
  • loadOrder ném RuntimeException khi file không có, không tự in lỗi; chỗ gọi quyết định.
  • Vòng đi-về: object, mảng, JSON, file, mảng. Đây là cách tạo và đọc dữ liệu API đơn giản.
